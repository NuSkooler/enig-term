# enig-term Phase 0 spike: B2 (icy_engine in WASM) vs B1

Date: 2026-10-24. icy_tools pinned at `1456074edac862d79d87ccd8cd4f0e87a57a9d39`.
Legend: **(V)** verified in this spike, with the test or command that shows it;
**(I)** inferred, not measured.

## Recommendation

**GO on B2**, with three conditions. Fall back to B1 only on the triggers
listed at the end of this section.

Reasons:

1. **It works end to end today (V).**
   - The B2 stack renders CP437 art, a SAUCE file and Topaz with Latin-1
     correctly in Chromium, WebKit and Firefox.
   - It got through every connect probe a real ENiGMA sends: DA, CPR, the
     font probe, `CSI 255n` and `CSI = 6 n`.
   - No fork of icy_tools was needed. Every engine gap was closed in a thin
     wrapper: `CoreSink` is about 170 non-comment lines of Rust.
2. **Frame cost is not the problem (V).**
   - A full 640x400 engine raster takes 0.4-0.8 ms in Chromium and WebKit
     and 1.8-3.8 ms in Firefox.
   - A one-character change re-rasters one 16-pixel band, not the frame.
   - Texture upload and the GPU pass are a fraction of a millisecond, apart
     from WebKit's software GL here.
3. **The TS shell is small and reusable whichever way this goes (V).**
   - It is 33.9 KB (12.5 KB gzipped), including the wasm-bindgen glue.
   - Telnet, replies, input, the WebGL2 pass and the layout all take an RGBA
     band, so B1 would reuse all of them unchanged. Choosing B2 is low-regret.
4. **Parity is what B2 buys.**
   - The emulations (RIP, IGS, SkyPix, PETSCII, ATASCII, Viewdata, sixel),
     DCS font loading, OSC palette and OSC 8 all come with the engine (V for
     ANSI, OSC, DCS and SAUCE; the others are compiled in but not exercised (I)).
   - B1 would have to rebuild every screen model except ANSI.

Conditions:

1. **Keep icy_engine's scrollback off** (done: the core defaults it to 0) and
   build our own cell scrollback in Phase 1. With the engine default, memory
   grows to around 1 GB over a session (V, below).
2. **Take the upstream asks to mkrueger** (list below). The size goal is only
   reachable with the dependency feature gates.
   - Accept about 2 MB gzipped for Phase 1.
   - Target 1 MB or less gzipped by Phase 2 (I: it depends on upstream).
3. **Pin and budget for churn.**
   - icy_tools had 310 commits in the 90 days before the pin, 19 of them to
     `parser_sink.rs` (V, GitHub API).
   - Four of its git dependencies have no rev, so our `Cargo.lock` is the
     real pin (V).
   - Plan a deliberate rebase per phase, not continuous tracking.

Switch to B1 if any of these holds:
- A sub-500 KB gzip budget becomes a hard requirement and upstream will not
  gate the image, archive and regex dependencies.
- Engine panics (which kill the instance) turn out to be reachable from host
  bytes in practice.
- Scroll-heavy throughput (0.2-1.8 MB/s, below) proves too slow on real
  phones.

### How to run

Toolchain:
- Node 22 (`mise.toml`).
- Rust stable with the `wasm32-unknown-unknown` target.
- `wasm-bindgen-cli` **0.2.129** (it must match the crate).
- Optionally binaryen `wasm-opt`.

Point the build at the tools with `WASM_BINDGEN=`, `WASM_OPT=`, and
`CARGO_TOOLCHAIN=` (default `stable`).

```sh
npm install
npm run build          # build:wasm (cargo, wasm-bindgen, wasm-opt -Oz) + build:js (esbuild -> dist/)
npm test               # tsc --noEmit, Node unit tests, Playwright (chromium, webkit, firefox)
npm run serve          # http://127.0.0.1:8090/ serves dist/ and /fixtures/
npm run bench          # browser bench -> docs/spike/bench-*.json, then test/bench-core.mjs
ENIG_TERM_LIVE_WS=ws://127.0.0.1:18810 npm run test:live
```

Page URL parameters: `endpoint`, `connect=1`, `aspect=0`, `crt=1`,
`sharp=0`, `blink=0`, `renderer=2d`, `cols`, `rows`. Test hooks: `naws=0`
and `debugDa=cterm`.

Notes:
- **WebKit on this host:** Playwright's WebKit needs `libevent-2.1-7t64` and
  `libavif16`, which are not installed. They were fetched with
  `apt-get download`, extracted into scratch, and started through a launcher
  given in `WEBKIT_EXECUTABLE=` (the Playwright config reads it). No root and
  no system change.
- **Playwright** is pinned to 1.60.0 to match the cached browser builds
  (chromium-1223, firefox-1522, webkit-2287).

What these show (all V):
- **Embedded fonts are about 3.0 MB raw but only about 350 KB gzipped**
  (204 `include_bytes!`, 2 `include_str!`). Stripping them alone does not
  make the binary small.
- **Hard-coding ANSI saves nothing.** LTO cannot drop RIP, SkyPix or IGS,
  because they stay reachable through the `Screen`/`EditableScreen`
  vtables.
- **What fills the rest** (twiggy on a symbolised font-stripped build, as a
  share of code bytes):
  - image codecs (zune_jpeg, image, jxl_*, image_webp, exr, tiff, png,
    quantette): about 29%;
  - core, alloc and std: about 20%;
  - regex (regex_automata, regex_syntax, aho_corasick): about 9%;
  - archives (lzma, sevenz, bz2, brotli): about 6%;
  - rayon: about 4%;
  - `icy_engine` plus `icy_parser_core`: about 10%.

  What keeps them alive is inferred from the code, not traced (I): likely
  `Screen::to_bytes` (every file saver), the APC image decode
  (`DrawJXLBlob`/`DrawPPMBlob`) and URL scanning.
- **`wasm-opt -Oz` makes the gzipped file about 3% *larger*** than
  wasm-bindgen's output (the stock "without wasm-opt" figure is taken from
  the identical ANSI-only build). Ship the un-optimised output, or try `-O2`/`-Os`.
- **`-O3` buys roughly 2x feed speed for +19% gzip** (Node, noisy).
- Only wasm-bindgen plumbing and `console.error` are imported from JS: no
  Date, no crypto (`grep __wbg_` on the glue). chrono and getrandom never
  reach JS.

### Frame cost in the browser (ms; engine raster / texture upload / GPU draw)

Each cost is averaged over batches of 300, because `performance.now()` is
coarsened to 0.1-1 ms without cross-origin isolation. Canvas is 1248x936,
frame 640x400, DPR 1. The GPU is software in all three:
- Chromium: SwiftShader (`ANGLE (... SwiftShader Device (Subzero))`);
- WebKit WPE: reports "Apple GPU", but it is a software path here;
- Firefox: the renderer is not exposed.

So the upload and draw columns are pessimistic (I) and the engine column is
the real cost (V).

| Browser | full frame | full frame with CRT | one char changed | one line scrolled | cursor move only | feed MB/s, no scroll | feed MB/s, scrolling text | scrolling feed + render per 4 KB |
|---|---|---|---|---|---|---|---|---|
| chromium | 0.80 / 0.19 / 0.03 | 0.59 / 0.12 / 0.02 | 0.17 / 0.04 / 0.01 | 0.74 / 0.13 / 0.01 | 0.11 / 0 / 0.01 | 27.0 | 1.83 | 0.65 |
| webkit | 0.36 / 0.03 / 1.87 | 1.50 / 0.06 / 3.40 | 0.32 / 0.01 / 5.22 | 0.53 / 0.05 / 2.03 | 0.08 / 0 / 2.33 | 15.6 | 1.29 | 0.57 |
| firefox | 3.76 / 0.09 / 0.47 | 1.79 / 0.09 / 0.56 | 0.43 / 0 / 0.46 | 1.81 / 0.09 / 0.52 | 0.33 / 0 / 0.53 | 6.0 | 0.21 | 0.19 |

Notes:
- The "full frame with CRT" engine column equals a plain full frame; CRT
  only adds GPU work. Differences between those two columns are noise.
- The bench yields one frame between phases. Without that, SwiftShader
  uploads became about 1000x slower after a few thousand back-to-back
  uploads and draws in one task: an order-dependent artifact, not a real
  cost (V: reversing the phase order moved the slowdown).

### Incremental updates (V, `core.test.mjs`, bench)

- **One-character change:** the engine re-rasters one text row (a 640x16
  band, 40 KB), and we upload that band with `texSubImage2D`. Not the full
  frame.
- **Scroll:** a full re-raster. icy_engine shifts every cell and does not
  mark lines dirty, so our cell-snapshot diff sees all 25 rows change.
- **Cursor-only move:** no raster; the cursor is a shader uniform.
- **Cost of the snapshot diff:** a no-change `render(false)` still costs
  about 0.1 ms, which is our snapshot diff (2000 dynamic `char_at` calls).
  It is cheap, but it runs every animation frame through `has_changes()`.
  Optimisation ideas for later: the engine's buffer version counter, or
  diffing only on feed.

## API fit (icy_engine for a terminal)

Each item gives what we did, then what to ask upstream.

1. **Host requests (V).**
   - Gap: `ScreenSink::request()` is a no-op; icy_term answers in
     `terminal_thread.rs`.
   - Ours: `CoreSink` wraps `ScreenSink`, captures each `TerminalRequest`
     with the state needed to answer it **when it was parsed** (a CPR after
     `CUP` but before more output in the same chunk reports the right
     position), and queues it for TS.
   - Upstream: nothing; this is fine.
2. **`CSI = Ps n` beyond 1-3 (V).**
   - Gap: these only surface as `report_error(MalformedSequence { sequence:
     "CSI = 6 n" })`.
   - Ours: we parse that string.
   - Upstream: a `TerminalRequest::CtermStateReport(u16)` or similar.
3. **`std::time::Instant` on wasm32 (V).**
   - Gap: `CSI ? 2026 h` (synchronized output) calls `Instant::now()`, which
     **panics**. The panic is an abort, so the whole instance is dead: "time
     not implemented on this platform", `RuntimeError: unreachable`.
   - Ours: we intercept the mode in `CoreSink`.
   - Upstream: `web-time` or an injected clock.
   - It is the only time call on the feed path (grep).
4. **Panics generally.**
   - wasm32 panics abort, so one reachable `unwrap` in the engine kills the
     terminal. Our panic hook logs the message to `console.error`.
   - Phase 1 needs "recreate the core and redraw" recovery (I: not built).
5. **Dirty tracking misses scrolls (V).**
   - Gap: `scroll_up/down/left/right` write cells through `layer.set_char`
     without marking lines.
   - Ours: partial renders also diff a cell snapshot.
   - Upstream: `mark_lines_dirty` in the scroll paths, a two-line fix.
6. **Scrollback is RGBA (V).**
   - Gap: `ScrollbackChunk::from_screen` rasterises every scrolled line
     (40 KB) and every clear (a full frame, 1 MB), and keeps up to 2000
     chunks (memory above).
   - Ours: the core sets the limit to 0. The raster still runs before the
     chunk is dropped, which is most of `CSI 2J`'s cost.
   - Upstream: a text-only scrollback mode. `variants/scrollback-text-only.diff`
     is a 3-line proof, and all 13 core tests pass on it.
7. **Fonts.**
   - Gaps:
     - `CsiFontSelection` ignores `Ps1`; every selection goes to the
       attribute-matched slot (ENiGMA always sends 0, so this is harmless
       today).
     - A selection of a DCS-loaded slot of 43 or above is reported as
       **Failure** after it actually took effect (V).
     - A font loaded at runtime into 0-42 is **overwritten** by the
       built-in table on selection (V).
     - Cell size always comes from slot 0 (`font_for_render(0)`), so an
       8x8 font under an 8x16 slot 0 sits in the top half (I from code).
   - Ours: the wrapper fixes the first three by intercepting
     `CsiFontSelection`. `load_font(slot, name, bytes)` accepts PSF1/PSF2,
     YAFF or raw 8xN and takes priority (V).
8. **External fonts and stripping the embedded ones.**
   - There is no cargo feature or cfg (V). `strip-fonts.py` shows the cost:
     204 + 2 macro sites. It has to keep CP437 8/14/16 and "IBM VGA",
     because `ScreenMode::Vga` and `BitFont::default()` call `unwrap()` on
     them.
   - With fonts stripped, the core boots, and Topaz loaded at runtime from a
     file renders and reports success (V).
   - Selecting a stripped font that was never loaded reports `ok` and
     renders blank glyphs (V). The wrapper must refuse it unless loaded.
   - Upstream: an `embedded-fonts` default feature, `get_ansi_font` returning
     `None` when the font is absent, and a font-provider hook.
9. **Dependency weight (V, measured above).**
   - Upstream: feature-gate `image`, `jxl-oxide`, `unarc-rs`, the GIF and
     quantette export, and the `FileFormat` savers. The terminal path needs
     none of them.
   - Without that, the size floor is about 1.6 MB gzipped. With it, about
     0.5-0.8 MB gzipped is plausible (I).
10. **Threading (V).** rayon falls back to the current thread on wasm32
    (renders are correct). `parking_lot` and atomics are fine
    single-threaded. No COOP/COEP needed.
11. **Ownership (V).** `Box<dyn EditableScreen>` plus
    `Box<dyn CommandParser>`, with `ScreenSink` borrowing the screen per
    `feed`: no friction with a single-threaded shell. Each render allocates
    a fresh `Vec<u8>`; a render-into-buffer API would avoid about 1 MB of
    churn per full frame (upstream nicety).
12. **Minor oddities (V).**
    - wasm-bindgen exports rav1e's `ChromaSampling` enum into our JS API (it
      comes through `image`).
    - A `[patch.crates-io]` for lzma-rust2 that icy_tools needs in its own
      workspace was *not* needed here.
13. **CTerm spec mismatches to settle (V by reading).**
    - Numbering: icy_term's CTDA list (1 fonts, 2 bright background,
      3 palette, 4 pixels, 5 font select, …) differs from the local
      `cterm.txt` (1 fonts, 2 palette, 3 pixels, 4 font select, …). We
      follow `cterm.txt`: `CSI < 0;1;2;4 c`, with only verified features.
    - icy_term's `CSI = 1 n` reply leaves out `pF` (first loadable slot);
      ours includes it (43).
    - ENiGMA's DA regex (`client.js:78`) accepts `=` and `?` but not `<`.
      So once ENiGMA sends `CSI < c`, its reply parser has to accept a `<`
      reply.
14. **Churn (V).**
    - 310 icy_tools commits in the 90 days before the pin, including 19 to
      `parser_sink.rs`, 10 to `icy_parser_core/src/lib.rs` and 7 to
      `screen.rs`.
    - `icy_sauce`, `retrofont`, `libyaff` and `codepages` are unpinned git
      dependencies upstream, so `crates/enig-term-core/Cargo.lock` is
      committed and is the real pin.

## Other findings

- **Sharp-bilinear (V).** The textbook form floors the scale and so becomes
  plain bilinear below 2x (visibly soft at 1.95x). We use icy's
  `sharpen_texel` form with the real scale, which is crisp at any scale
  (compare the testcard and dpr2 shots).
- **4:3 rule (I, design choice).** Vertical stretch =
  `(80 x cell width) / (25 x cell height) x 3/4`:
  - VGA 8x16 gives 1.2; 9x16 gives 1.35; EGA 8x14 gives 1.371 (all three
    match icy's constants);
  - 8x8 gives 2.4 (NTSC).

  The Ami/X profile would override it (PAL 80x32 needs about 1.875).
- **Canvas sizing (V).** Chromium and Firefox report
  `devicePixelContentBoxSize` and use it. WebKit (WPE here) does not have
  it, like Safari (probed: `'devicePixelContentBoxSize' in
  ResizeObserverEntry.prototype` is false), so it takes the fallback: the
  CSS size snapped to a whole number of device pixels, then `canvas.width =
  css x dpr`. The DPR 2 test passes in all three, so both paths are
  covered.
- **CRT port (V).**
  - Curvature, scanlines, noise and sync wobble, `adjust_color` and the
    monitor tints are lifted.
  - Scanlines were changed to one beam profile per source row. icy darkens
    every other output pixel, and two lines per row aliased into moiré
    under curvature.
  - Some moiré remains on large solid areas at DPR 1.
  - icy's bloom normalises by the *thresholded* weight sum, so any bright
    neighbour gives a full-strength halo: dense text gets grey boxes. It is
    off in our preset.
- **Input (V, Playwright on all three engines).**
  - Verified: CP437 and Latin-1 typing, arrows, Home (`CSI H`), End
    (`CSI K`), PgDn (`CSI U`), F1 (`ESC O P`), Ctrl+letter, and replies
    going out through the same path.
  - Not verified: IME composition and Gboard on a real device (I).

  - transfers.

# Phase 4 spike: which ZModem (icy_net in WASM vs zmodem.js)

Date: 2026-10-26. **(V)** verified by running, **(I)** inferred.

## Decision

**icy_net's ZModem, compiled to WASM** (`crates/enig-term-zmodem`,
`enig-term-zmodem.wasm`). It passed the same harness where zmodem.js failed
everything against sexyz, it recovers from damaged data where zmodem.js by
design does not, and it is maintained. The cost is a 70 KB gzipped WASM,
loaded only for a transfer, and eight small patches (six of them fixes to
offer upstream).

## Candidates

| | icy_net (icy_board `crates/icy_net`) | zmodem.js 0.1.10 (FGasper) |
|---|---|---|
| Licence (V, read in the sources) | Apache-2.0 (repo `LICENSE`; no NOTICE, no per-file headers; `constants.rs` quotes Omen Technology's ZMODEM.H) | Apache-2.0; its one dependency, crc-32 (SheetJS), Apache-2.0 too |
| Maintenance (V, GitHub API, 2026-10-26) | last commit 2026-10-15; 100+ commits in the 90 days before, 41 of them touching `crates/icy_net` | last commit 2020-09-03, last release 0.1.10 (2020-08) |
| Form | Rust, async, pulls bytes from a `Connection` | JS, push model (`Sentry.consume`) |
| Size shipped (V) | WASM 148 KB, **70 KB gzipped**; driver in `enig-term-xfer.js` (8 KB gzipped with X/YModem) | 33 KB, about 11 KB gzipped |

Also looked at, not spiked: `zmodem-ts` 1.0.8 (a TypeScript fork of
zmodem.js relabelled MIT, which an Apache-2.0 work's fork cannot simply do)
and `zmodem2` 1.4.0 (zmodem2-js: a port of the Rust zmodem2 crate whose
README says part of the code was generated by an LLM). Both were set aside
on provenance.

## Harness

One harness (`scratchpad/p4/harness/harness.mjs`, kept out of the repo),
two adapters with the same interface. It runs the real programs over pipes
(lrzsz `sz`/`rz`; `sexyz -raw sz`/`rz`) and checks byte-identical files:
small, 70,000 bytes with every byte value and runs of the bytes ZModem and
Telnet escape, an empty file, a batch of three, 10 MB; both directions; a
local cancel and a remote abort (SIGINT to the program) at about 2 MB. A
cancel or abort passes only if both ends stop by themselves (an engine left
waiting fails).

## Results (V)

| | icy_net, 3 patches | zmodem.js |
|---|---|---|
| lrzsz, 10 transfer cases | 10/10 | 10/10 |
| lrzsz, cancel and abort (4) | 4/4 | 2/4 (down: a cancel left `sz` running 15 s; an abort only ended when `sz` exited, 60 s) |
| sexyz, 10 transfer cases | 9/10 (the empty-file download: a sexyz bug, below) | **1/10** (only the 14-byte download) |
| sexyz, cancel and abort (4) | 4/4 | 0/4 |
| **total** | **27/28** | **13/28** |
| 10 MB down / up, ms (Node, pipes; noisy, a loaded host) | 1,653 / 127 | 1,200 / 1,122 (a second run: 1,959 / 1,420) |

Why zmodem.js fails against sexyz (V, with `Zmodem.DEBUG`):
- Uploading, it sends a ZSINIT (to make the receiver escape control
  characters); sexyz's `zmodem_recv_init` does not take ZSINIT ("received
  ZSINIT instead of ZFILE or ZFIN") and repeats its ZRINIT; zmodem.js then
  drops that ZRINIT and the following ZRPOS as "Unhandled header", stalls,
  and sexyz times out (20 s, the file arrives late or not at all).
- Downloading anything larger than one subpacket, it fails with "Unhandled
  header: ZDATA".
- By design it assumes a reliable line ("It is assumed that no error
  correction will be needed"): no ZRPOS recovery, no timeouts. Under ENiGMA
  that matters, because sexyz's status text shares the pty with the protocol
  (below).
Fixing it would mean taking over an unmaintained library's state machine.

Why icy_net needed patches (V):
1. **0001, the port**: no transports, X/YModem or Kermit; `Instant`, sleep,
   timeouts, the file reader and the temp file come from `rt.rs` (on
   wasm32-unknown-unknown `Instant::now()` panics, and there is no file
   system).
2. **0002**: a CAN abort inside file data was taken for line noise; the
   receiver then waited for ever (the lrzsz remote-abort case hung).
3. **0003**: after one damaged byte, lrzsz's `rz` repeats its ZRPOS while it
   skips the stale stream; icy_net restarted on each repeat and the two ends
   ping-ponged until `rz` gave up (2 of 2 runs). With one ZRPOS honoured per
   offset per second, 16 of 16 corruption runs (4 offsets, both directions,
   both programs) arrive byte-identical.
4. **0004**: upload data awaited from the host a window at a time (a 10 MB
   upload never sits in WASM memory), and a file the host will not keep is
   skipped (ZSKIP) instead of failing the batch.

Two more came from running under a real board's pty, where the program's
status text is in the stream (V, `test/zmodem.test.mjs` "status text in the
stream" and the fake BBS):
5. **0005**: icy_net's sender counted every byte before a ZPAD as a header
   error and aborted after three ("rz waiting to receive.", sexyz's banner).
6. **0006**: text spliced into a data subpacket made it overlong, which was
   fatal; it is now a damaged subpacket and asked for again.
7. **0007**: the ZFILE info carried only name and length; sexyz then dated
   ENiGMA uploads in the year 2446 (V, the file area). It now carries the
   modification time and what is left of the batch.
8. **0008**: in the live matrix a ZModem download whose file had arrived
   whole failed at the end with "Got ZDATA before ZFILE": a resend answering
   an earlier ZRPOS reached the receiver after it had closed the file. A
   stale ZDATA after a file is now ignored (ZRINIT again).

The one remaining harness failure is sexyz's: it cannot send an empty file
with ZModem. It rejects the receiver's ZRPOS 0 ("Received INVALID ZRPOS
offset: 0", `zmodem_handle_zrpos` in the installed `master/1aab983e01`
build) against lrzsz's `rz` as well (V, sexyz piped to `rz`); zmodem.js
fails that case too. enig-term's receiver ends cleanly there (an inactivity
timeout, or the board's menu when it returns).

## Robustness, as shipped

- Damaged data: ZRPOS recovery both ways (patches 0003, 0006); the fuzzer
  (`npm run fuzz:xfer`, 100,000 mutated sessions in a minute, none failing)
  checks that a file reported complete is byte-identical (V).
- Aborts: CAN in data (0002), in headers (upstream), from our side (icy_net's
  abort sequence; data still in flight is drained, and the abort repeated
  while it keeps coming) (V).
- Timeouts: icy_net has almost none (its ZRINIT resend is commented out); the
  driver ends a transfer after 60 s without traffic either way, and when the
  board draws its menu again (V).
- Resume: the sender seeks on ZRPOS (V, the corruption runs); the receiver
  always asks for offset 0 (a browser cannot append to a saved file).
- Big files: uploads read in windows (0004); downloads stream out as events
  of up to 64 KB, and a sink that returns a promise holds the session (V).
- A Rust panic aborts the instance: the transfer fails with the panic
  message, and the next transfer instantiates the module again (I: no panic
  was seen in testing, so this path is untested).

## Upstream asks (icy_board / icy_net), numbered after the earlier ones

25. A `no-std-fs`/wasm feature: an injected clock and file source/sink, so
    patch 0001 is not needed.
26. Patch 0002: treat ZDLE CAN CAN CAN CAN (five CANs) inside a data
    subpacket as the abort.
27. Patch 0003: ignore a repeated ZRPOS for the same offset while the
    restart is in flight.
28. Patches 0005-0008: skip noise before headers in the sender, treat an
    overlong subpacket as recoverable, send the modification time (and
    files/bytes left) in ZFILE, and ignore a stale ZDATA after a file.
29. A receive-side inactivity timeout and the ZRINIT resend (commented out
    in `rz.rs`), so a vanished sender does not leave the receiver waiting.
30. Expose the receiver's state (in a file or between frames), so a host can
    tell protocol data from a board's screen without heuristics.
